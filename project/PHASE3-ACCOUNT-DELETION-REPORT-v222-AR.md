# استكمال المرحلة الثالثة — حذف الحساب بأمان (v222)

## ملخص التسليم
أُضيف مسار حذف حساب من داخل إعدادات الأمان، مع تنفيذ الحذف من Cloud Function موثوقة باستخدام Firebase Admin SDK. الحذف لا يتم من المتصفح مباشرة، ويتطلب إعادة إدخال كلمة السر، ثم جلسة موثّقة حديثًا، وتأكيدًا نصيًا صريحًا.

## ما تم تنفيذه
- إضافة قسم «حذف الحساب نهائيًا» في إعدادات الأمان.
- اشتراط كتابة «حذف حسابي» وإدخال كلمة السر الحالية ثم تأكيد نهائي إضافي.
- إعادة التحقق من هوية المستخدم بواسطة Firebase Auth قبل استدعاء الخادم.
- إضافة Cloud Function `deleteMyAccount` في منطقة `europe-west1`، ترفض الطلب إذا لم يكن المستخدم مسجّلًا أو لم تكن الجلسة حديثة (خلال 5 دقائق) أو لم يرسل تأكيد الحذف.
- حذف المنشورات المملوكة للمستخدم مع محتواها الفرعي، وملفات صور المنشورات من Storage.
- حذف التعليقات التي كتبها على منشورات الآخرين مع إصلاح عدّادات التعليقات وآخر تعليق.
- حذف الحالات المملوكة له ومشاهدات الحالات التي سجلها على حالات الآخرين.
- حذف رسائله من جميع المحادثات، حتى المحادثات التي غادرها سابقًا، مع ملفات الصور/الصوت المرتبطة برسائله. رسائل بقية المشاركين تظل موجودة.
- إزالة المستخدم من المحادثات والمجموعات؛ وإذا كان مشرف مجموعة يتم نقل الإشراف لأول عضو باقٍ، وإذا لم يبقَ أعضاء تُحذف المحادثة والمجتمع المرتبط بها.
- حذف إعجاباته على منشورات الآخرين مع تصحيح عدّاد الإعجابات.
- إزالة علاقات المتابعة والصداقة وطلبات الصداقة والحظر الواردة إليه، وإزالة اشتراكاته بالقنوات وتصحيح أعداد المتابعين.
- إزالة مشاركته ودعوته من الفعاليات، وحذف البلاغات التي أرسلها.
- إزالة سجلاته المعروفة في ملفات الحساب والملف العام والصورة والهاتف والميلاد والحضور والشكل والاقتصاد وحالة العالم والتصميمات الخاصة.
- إزالة ملفات تخزين المنشورات ووسائط المحادثات وملفات السينما الخاصة بالمستخدم ضمن مسارات الغرف المعروفة.
- حذف مستند الحساب وكل المجموعات الفرعية التابعة له، ثم حذف مستخدم Firebase Authentication في نهاية العملية.
- جعل العملية قابلة لإعادة المحاولة عند فشل جزئي: لا يُحذف مستخدم Authentication إلا بعد اكتمال التنظيف السابق. قد تُحذف بعض البيانات بالفعل قبل حدوث خطأ، وتستكمل المحاولة التالية ما تبقى.
- تنظيف بيانات الجهاز المحلية بعد نجاح العملية.

## الملفات المعدّلة
- `backend/firebase-functions/index.js` — وظيفة الحذف والتنظيف الخادمي.
- `site/chanse3/settings.js` — واجهة الحذف وإعادة التحقق والتأكيد.
- `site/sw.js` — تحديث مساحة التخزين المؤقت إلى v222.
- `site/version.json` و`site/chanse4/version.json` — تعريف المرحلة 222.
- `package.json` و`site/package.json` — إضافة اختبار v222.
- `scripts/v222-account-deletion-check.mjs` — اختبارات تحقق ثابتة.
- `scripts/account-monitor-check.mjs` — حصر فحص عدم قراءة الرسائل الخاصة في مسار لوحة الإدارة فقط، لأن وظيفة حذف الحساب تحتاج قراءة رسائل المستخدم من الخادم لتنظيفها.
- هذا التقرير.

## الاختبارات
- `npm test`: نجح بالكامل بعد إضافة اختبار v222 وتحديث فحص لوحة الإدارة.
- `node --check backend/firebase-functions/index.js`: نجح.
- `node --check site/chanse3/settings.js`: نجح.
- `node --check scripts/v222-account-deletion-check.mjs`: نجح.
- `npm run lint` داخل `backend/firebase-functions`: نجح.
- `npm run build`: لم ينجح لأن Vite غير مثبت في بيئة التنفيذ (`vite: not found`).
- لم يتم اختبار حذف حساب تجريبي على Firebase Emulator أو Firebase حقيقي، ولم يتم النشر إلى Firebase أو GitHub Pages.

## متطلبات التفعيل
1. نشر Cloud Function الجديدة: `firebase deploy --only functions:deleteMyAccount` من جذر المشروع بعد تثبيت Firebase CLI وتسجيل الدخول واختيار مشروع Firebase الصحيح.
2. لا توجد تغييرات جديدة على Firestore Rules أو Storage Rules في v222؛ وظيفة Admin SDK تعمل بصلاحيات الخادم.
3. اختبارها أولًا بحساب تجريبي غير مهم: إنشاء منشور وتعليق وحالة ومحادثة، ثم تنفيذ الحذف والتحقق من حذف الحساب ومحتواه، وبقاء محتوى المشاركين الآخرين.
4. التأكد من إعدادات Storage bucket ومشروع Firebase الصحيح قبل النشر.

## حدود معروفة يجب عدم إخفائها
- الاختبارات الحالية ثابتة/ساكنة؛ لم تُثبت بعد سلوك الحذف على مشروع Firebase فعلي.
- التنظيف يغطي مجموعات البيانات ومسارات التخزين المعروفة في المشروع الحالي. أي مجموعة قديمة أو مخصصة غير موثقة أو ملفات Storage محفوظة خارج المسارات المعروفة قد تحتاج إضافة صريحة.
- حذف الرسائل يزيل رسائل المستخدم نفسه فقط؛ لا يمسح رسائل الآخرين في المحادثات المشتركة.
- في حال فشل العملية أثناء التنظيف، قد تكون بعض بيانات الحساب قد حُذفت بالفعل بينما يظل سجل Authentication قائمًا حتى إعادة المحاولة بنجاح.
- لا يُعدّ الحساب محذوفًا فعليًا للمستخدمين حتى نشر الوظيفة واختبارها على Firebase.
