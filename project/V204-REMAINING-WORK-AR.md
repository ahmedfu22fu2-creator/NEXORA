# THE SQUAD — قائمة الإكمال المتبقية بعد v204

هذه القائمة تفصل بين وجود كود/واجهة في المستودع وبين إثبات عمل الميزة في بيئة حقيقية. لا تعتبر أي ميزة مكتملة إنتاجياً لمجرد وجود ملفاتها أو نجاح اختبار ساكن.

| المجال | ما يمكن إثباته من الحزمة | ما يلزم قبل إعلان الاكتمال |
|---|---|---|
| الحسابات والهوية | مسارات تسجيل/دخول وملفات هوية موجودة واختبارات تكامل ساكنة | اختبار حسابات فعلية، استعادة كلمة المرور، الجلسات، والتحقق من صلاحيات المستخدم |
| المنشورات والقصص والقنوات | وحدات وواجهات واختبارات wiring موجودة | اختبار نشر/تعديل/حذف ورفع وسائط وقواعد وصول على Firebase staging |
| الرسائل | حدود استعلامات ومرفقات محلية واختبارات أمان مصدرية | اختبار مراسلة بين حسابين، القراءة/عدم القراءة، الوسائط، الحظر، وإشعارات الخلفية |
| المكالمات | WebRTC وICE/TURN wiring وواجهات تحكم موجودة | HTTPS فعلي، إعداد TURN صالح، جهازان/شبكتان، أذونات الكاميرا والميكروفون ومشاركة الشاشة |
| المدينة ثلاثية الأبعاد | ملفات عالم/مدينة وأصول GLB محدودة الحجم موجودة | تشغيل Browser/WebGL، اختبار الحركة والتصادم والأداء على أجهزة ضعيفة، والتحقق من تعدد اللاعبين الحقيقي |
| السيارات والمعارض | أصول سيارات وبعض أنظمة العرض/التخصيص موجودة | جرد يثبت 20 طرازاً مستقلاً و5 معارض ثلاثية الطوابق، ثم قيادة وشراء وملكية محفوظة على الخادم |
| العقارات | محركات/واجهات مرتبطة بالعالم موجودة | دورة شراء وملكية وصلاحيات دخول وديكور محفوظة ومختبرة |
| المحفظة والاقتصاد | Cloud Functions وحواجز دفتر الأستاذ موجودة واختبارات مصدرية | مراجعة أمنية واختبارات معاملات متزامنة على staging، وعدم تمكين قيمة مالية حقيقية دون تصميم مستقل |
| لوحة الإدارة | واجهات مراقبة ونداءات callable محمية موجودة | اختبار حساب مالك/مشرف فعلي، تدقيق السجلات، وقياس الأداء على بيانات تجريبية |
| النشر | ملفات Firebase وHosting وإعدادات build موجودة | تثبيت التبعيات، build ناجح، إعداد أسرار خارج المستودع، deploy staging، ثم موافقة صريحة للنشر النهائي |

## بوابات الإصدار الإلزامية

1. تثبيت الاعتماديات من ملفات lock موثوقة (غير متوفرة في هذه الحزمة حالياً) ثم نجاح بناء Vite.
2. تشغيل Browser QA على الكمبيوتر والموبايل مع صور/سجل نتائج.
3. توفير Firebase staging ومستخدمين تجريبيين؛ عدم استخدام حسابات أو بيانات إنتاجية في الاختبار.
4. إكمال اختبارات تدفق حقيقية للأنظمة الاجتماعية والاقتصاد والمدينة والمكالمات.
5. مراجعة أمنية لقواعد Firestore وStorage وCloud Functions قبل النشر.
6. نشر staging أولاً، ثم النشر الإنتاجي فقط بعد موافقة صاحب المشروع.

## ملاحظة صريحة

لا يمكن من ملفات المصدر وحدها إنشاء حساب Firebase أو استخراج أسرار المشروع أو نشر الموقع إلى حساب المالك. هذه الاعتمادات يجب توفيرها من صاحب المشروع عبر قناة آمنة عند الوصول لمرحلة الاختبار/النشر.
